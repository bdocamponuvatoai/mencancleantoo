# Migration verification — 2026-10-30

The original site (static HTML generated by a Python script, with a hand-written stylesheet and script) was migrated to Next.js 16.4.3 / React 19.3.1. Before anything was deleted, the original build was copied aside and used as the baseline for every comparison below.

## Method

- Both builds were served by the same small Node static server (directory `index.html` support, `404.html` fallback).
- Browser: system Google Chrome 156.0.8078.73 on Windows 11, driven by `playwright-core` 1.64.1. Reduced motion on, device scale factor 1.
- Before each capture: every image was forced to `loading="eager"` and awaited with `img.decode()`, then `document.fonts.ready`, then two animation frames. The mouse was parked at (0,0), animations disabled, and full-page screenshots retaken until two consecutive captures were byte-identical.
- Pixel diffs: `pixelmatch` 8.0.0 at **threshold 0** (any channel difference counts).
- Chrome was launched with `--disable-gpu --disable-checker-imaging --force-color-profile=srgb --disable-partial-raster`. Without these flags an A/A run (the original site compared with itself) differed in 6 of 84 captures, always inside photographs (image re-rasterisation timing). With them the A/A run differed in 0 of 84, so every result below uses them.

## Build and static checks

- `npm run build`: 17 static pages, including six service pages from `generateStaticParams`, `robots.txt`, `sitemap.xml`, `icon.svg` and the 404 page.
- `npm run check` (typecheck + ESLint + Prettier): passes.
- `npm audit --omit=dev` and the full `npm audit`: 0 vulnerabilities.

## Phase 4: parity before cleanup

### Pixel parity

14 URLs × 6 widths (1600, 1280, 1024, 768, 390, 320 px) = 84 full-page captures. URLs: `/`, `/services/`, all six service pages, `/about/`, `/contact/`, `/plan/`, `/plan/?service=commercial-cleaning`, `/privacy/` and an unknown URL (404).

**Result: 84 / 84 pixel-identical (0 differing pixels).**

One real difference was found and fixed along the way. Manrope has no arrow glyphs (`→`, `←`), so they fall back to the next font in the stack. `next/font` inserts a size-adjusted "Manrope Fallback" ahead of Arial by default, which moved the arrows on the plan buttons and the "← All services" breadcrumb by up to 19 px of anti-aliasing. Setting `adjustFontFallback: false` restores the original stack (`Manrope, Arial, sans-serif`), and those diffs went to 0.

### Computed layout

For every rendered element on every page and width: tag sequence, bounding box (±0.05 px) and 21 computed style properties were compared.

**Result: identical everywhere**, except for two differences with no visual effect (see "Accepted differences" 1 and 2).

### CSS split

The original 36 KB stylesheet was split into 19 partials with a postcss script. Each rule was classified by selector prefix, with any unclassified selector treated as a failure. Declarations: 1,516 originally, minus 4 in the dropped `@font-face` (replaced by `next/font`), plus 2 font tokens = 1,514 in the output, as asserted. Splitting changes the order of some rules. All 4,935 reordered pairs that have equal specificity and overlapping properties were checked against the real DOM of every page with state classes forced on. Only 6 shared an element, and all 6 were `*:before`/`*:after` pseudo-element rules, not real conflicts.

### Behaviour parity

The same scripted interactions ran on both builds and the JSON outcomes were compared:

- Mobile menu (390 px): open, Escape (focus returns to the toggle), navigate and close.
- Finder: each option by click, Enter and Space. `aria-pressed`, title, copy, link `href` and link text all match.
- Before/after slider: End, Home, arrow keys, PageUp and click. `--reveal`, value and `aria-valuetext` all match.
- FAQ open states.
- Plan builder at 1280 and 390 px:
  - "no service" error and focus;
  - property/frequency defaults when switching between Deep, Commercial and Recurring;
  - empty and whitespace-only city errors, and Enter on an empty city (native validation message);
  - Enter to advance;
  - priorities, and notes with special characters;
  - **Back keeps every value**;
  - review rows;
  - booking title, copy, href and text for residential and commercial;
  - **the exact `mailto:` href**;
  - downloaded file name and full contents, and the status message;
  - "Edit my choices" keeping values;
  - presets `?service=` move-cleaning, rental-turnovers, commercial-cleaning, recurring-cleaning and an invalid value.

**Result: every outcome identical**, apart from accepted differences 3 and 4. Console errors: 0 on both builds.

State screenshots (element captures): open menu, finder initial state, slider at 0% and 100%, FAQ open, and six plan states at each of two widths. **17 / 17 identical.** The other 3 are the finder after a click (accepted difference 3).

There is no clipboard behaviour in the original site, so there was nothing to compare.

### Accepted differences

1. `next/image` always inlines `color: transparent` on `<img>`, which hides alt text while the image loads. It has no effect once the image has loaded, and 0 pixels differ.
2. On `/plan/`, hidden step 4 of the original's static HTML contains an arrow `<span>` that its script replaces with plain text before the step is ever shown. The Next build renders the plain text directly. The element count differs by one inside a hidden section; the visible step-4 screenshots are identical.
3. **Finder arrow (approved).** In the original, clicking "My home / My move / My business" replaced the link's arrow `<span>` with plain text. The arrow shrank from 19 px to 13 px and the box got 9 px shorter, so the page below jumped. The Next build keeps the arrow as it appears on load. Link text, `href` and every other state are identical.
4. **Menu on resize (added).** If the mobile menu is open when the window widens past 700 px, it now closes (`aria-expanded="false"`). The original left it marked open. The desktop navigation looks the same either way.
